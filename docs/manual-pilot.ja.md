# 最初の手動実験

この手順は、まだ実行エンジンがない段階で、既存のファイルを扱えるAIエージェントと試すためのもの。ここに書かれた手順を収録しただけでは実施済みにならない。自動タスクは設定しない。

1. この公開repoの外に、非公開の実験用フォルダを作る。最初は[合成イベント](../examples/events.synthetic.jsonl)を使い、実際の会話ログを投入しない。
2. [設定例](../configs/pilot.example.json)をコピーし、対象、実行環境、モデル、上限を決める。初回はLight＋Deepのみとし、REM・日記・定期実行は無効のままにする。費用が不明ならモデル呼び出しは行わず、手動で形式だけ確認する。
3. 過去の経験用ログ、調整用課題、独立した評価課題を分ける。初回は[評価計画](evaluation.ja.md)の接続確認5件から始める。
4. 別の新しいセッションで、[整理プロンプト](../prompts/sleep-consolidator.ja.md)、経験用ログ、現在の記憶だけを渡す。評価用課題・正解は渡さない。
5. 出てきた候補を原ログと照合する。出典・scope・秘密・生成物の自己循環も確認する。根拠不足はcandidate、明示的な訂正や検証結果で確かめられた項目だけverifiedにする。
6. 一時的なcandidate snapshotを作り、A（原ログ検索）とB（記憶＋原ログ検索）で同じ評価課題を解く。各試行を新しいセッションにし、他条件の回答は見せない。
7. [レポート雛形](../templates/experiment-report.ja.md)に全試行、失敗、費用を記録する。採用判定が終わるまでactive版は変えない。
8. 試験採用の条件を満たし、原証拠のhash・削除／失効状態・親版が変わっていない場合だけ、新しい記憶版を次回用に指定する。効果が不明なら原ログ検索の構成を維持する。

## エージェントへ渡す最初の依頼例

> このフォルダの合成ログを、sleep-consolidatorの指示に沿って整理してください。外部ネットワーク、GitHubへの投稿、コードの実行は不要です。候補と根拠を列挙し、根拠不足は保留してください。まだactive memoryを更新せず、評価用課題も読まないでください。

これは手順の例であり、すべてのエージェント製品に共通の実行コマンドではない。実際に渡せるファイルや永続保存先は、使う環境で確認する。

## REMを追加する場合

A/Bの後、別の開発用データと予算で[REMプロンプト](../prompts/dream-reflector.ja.md)を試す。出力は仮説と検証案だけにし、元の証拠による確認を経てから候補snapshotへ含める。[R条件](evaluation.ja.md)で追加効果を比較する。日記を作る場合も非公開で保存し、通常取得と次回の証拠入力から除く。

## 最初の成功条件

正しいJSONが出ることだけでなく、訂正を反映できること、根拠なしの候補を保留できること、古い記憶をそのまま採用しないことを確かめる。性能の結論は独立したA/B評価の後に出す。
