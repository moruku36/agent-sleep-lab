## 実際に動かした流れ

| 段階 | 観測した結果 |
|---|---|
| 記録 | レビュー済みの公開文書1件を、合成と偽らず実eventとして専用SQLiteに保存 |
| 生成 | 実際のモデル応答から未採用候補1件を生成。claim本文は2,080 UTF-8 bytes |
| レビュー | 別の根拠確認担当が候補の正確な本文と原資料のhashを照合 |
| 採用 | 検証・評価receiptを別に登録し、既存の原子的writerで記憶1件を採用 |
| 取得 | 適格な記憶1件を4,010-byteの参考bundleとして取得。取得によるDB書込みは0件 |
| 別の作業で利用 | 原文のみ／同じ原文＋採用記憶の2条件で、実際の回答を各1件取得 |

回答後にも原資料・policy・採用snapshotが変わっていないことを確認しました。
生成と次の作業は明示的なモデルへの引渡しで行い、台本のfixture応答ではありません。
ハーネスがモデル呼出しを自動dispatchしたわけではありません。
別の担当によるレビューは、認証済みprovider証明や独立した科学的holdoutではありません。

ローカル拡張は、既定の合成専用入口による実データ拒否を維持しました。
不変URL・レビュー済み原資料hash・限定scope・許可revision・期限を備えた1資料限定の
明示境界と、実データ用のDB／receipt／bundle識別を追加しています。
JSON保存だけを採用扱いにせず、既存の原子的採用を再利用しました。
