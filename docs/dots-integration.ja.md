# ChatGPT dots との接続設計：忘れることを前提にする

状態：提案。設計のみで、接続はまだない（2026-11-08）。

## 1. 前提（公式仕様として確認したこと）

ChatGPT dots は、クラウド上で動く常時稼働エージェントである。公式ドキュメントで、次の範囲を確認した。

- dot が保持するノートは、会話の完全なトランスクリプトではない。
- 新しいタスクは、過去の会話全体を自動では引き継がない。
- 引き継がれる文脈は、直接の会話、背景処理、他への委譲など、場面ごとに異なる選択集合になる。
- 個別のメモリ項目を、外部から閲覧・修正・削除することはできない。
- Memory を無効にしても、既に渡した情報は消えない。文脈の消去は会話の削除による。

つまり「忘れる」は不具合ではなく仕様の範囲である。この接続では、忘れることを前提に設計する。出典は末尾に置く。確認日は 2026-11-08 で、仕様は変わりうるため、実装時に公式ドキュメントを読み直す。

## 2. 設計原則

1. **正本は外部に置く。** 決定事項と作業状態の正本は、このハーネスの verified 記憶と状態スナップショットに置く。エージェント内部の記憶は補助的なキャッシュとして扱い、根拠にしない。
2. **想起はタスク依頼に同梱する。** 取り込み口は依頼の文面しかないため、Retriever の出力は「想起バンドル」として依頼に含める。エージェントが自分で取りに来る設計にはしない。
3. **状態は毎回渡す。** 作業状態のような変動情報は長期記憶へ移さず、正本を外部に置いて、依頼ごとに時点つきの最新スナップショットを渡す（[全体設計](architecture.ja.md)の「変動情報は長期記憶へ安易に移さない」と同じ）。
4. **応答しないことを状態として扱う。** 依頼には一意なキーを持たせ、未応答・実行中・完了・失敗を区別する。再送で同じ作業を二重に実行しない。応答がなかった依頼を「忘れた」と記録しない。
5. **依頼はタスク単位に区切る。** 長い単一スレッドの継続に依存しない。これは、長い会話でクライアントの操作が劣化するという公開報告と、タスクごとに新しいスレッドを使うという公式の案内とも整合する。

## Sleep / dreamingとの境界

[Sleep / dreaming設計](dreaming.ja.md)は対象の外部で走る処理である。dots内部の記憶・背景処理・権限を変更する接続は想定しない。対象にはactive版の想起バンドルを渡し、REMの仮説や日記は通常の指示・確定事項へ混ぜない。新しい依頼への応答をsleep完了待ちにせず、最後の有効版を使う。

## 3. 想起バンドルの形式（案）

依頼に同梱する想起バンドルは、次の範囲に絞る。

- 目的と完了条件
- 確定した決定事項（根拠への参照つき）
- 現在の状態スナップショット（時点つき）
- 関連する verified 記憶（全体設計の注入上限の範囲内。初期は 2,000 トークン）
- 正本の参照先

現在のユーザーの指示が、想起内容より優先される（全体設計どおり）。古い状態スナップショットを新しい依頼へ使い回さない。バンドルが長いほど、コストと対象側の処理負荷が増えるため、関連性の低い項目は入れない。

## 4. capture のイベント源

- 非同期のメッセージ基盤（GitHub リポジトリ上のファイル交換）に残る、依頼・状態共有・結果報告・訂正をイベントとして取り込む。会話の全文ではなく、依頼と結果と訂正を正とする。
- エージェントの自己申告は観測として記録し、それだけで verified にはしない（全体設計の Verifier と同じ）。
- 未応答の依頼は pending として残す。督促や再送の判断は、人の判断か、対象側の運用ルールに従う。

## 5. 無応答・障害への備え

公式ステータスには dots の障害が繰り返し記録されている（例：2026-11-05 の「ChatGPT Work and Dots Errors」、2026-10-07 の応答失敗・遅延）。無応答のときは、記憶の問題と決めつけず、まず次を確認する。

1. 公式ステータスに障害が出ていないか。
2. 対象側の Activity に承認待ち（pending decision）が残っていないか。
3. 一時停止／再開、再起動で回復するか。
4. 時間をおいて再確認する。

Reset は不可逆で最終手段とし、このハーネスからは実行しない。障害で届かなかった依頼は、障害として記録し、記憶の欠落とは区別する。

## 6. この対象で測ること

評価の枠組みは[評価計画](evaluation.ja.md)に従い、この対象では次を数える。

- 決定済み事項が、再び質問・再確認された回数
- 同じ失敗や同じ調査の再発回数
- 未応答のまま放置された依頼の件数と滞留時間
- 想起バンドルのトークン量と、作成・維持の費用

比較条件は、想起なし／原ログ検索のみ／想起バンドルあり、を分ける。

## 7. 境界

- 対象エージェントの実行権限・公開方針は変えない。接続は依頼と結果の受け渡しに限る。
- 実際の会話ログと私的な記憶は公開 repo に入れない（全体設計の保存と公開の分離どおり）。
- この文書は設計提案であり、接続の実装や効果の実測はまだない。
