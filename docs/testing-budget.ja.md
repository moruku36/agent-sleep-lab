# 個人開発のテスト上限

[ホーム](../README.ja.md) | [Implementation status](implementation-status.ja.md)

2026-11-10の所有者方針：**1回の開発試行で実行するテストは合計10件以下。通常は変更に関係する3〜5件を、1回だけ実行します。** ローカル・CI・再実行も同じ試行の合計へ数えます。コマンドやjobを分けて上限をリセットしません。

以前の「174テスト合格」は、一括実行の中の検査項目数で、174回の個別再実行ではありません。ただし毎回174件を走らせる必要はないため、この運用を変更しました。過去のテストコード・実行記録は削除せず保持しますが、新しいcommitで全件を再確認したとは表示しません。

## 実行入口

`tests/run_tests.py`は変更ごとの明示選択を使います。現在のレビュー修正案は新規5＋既存5の10項目。固定3件だけでは共有経路の回帰が不足する指摘に対応しましたが、同じGate3試行13項目・4回の承認枠は使い切りであり、追加10項目を1回実行する明示承認まではPR／CIを作成しません。変更に応じてunittestの具体的なテスト名を渡し、最大10件までに制限します。大きなclass/moduleや重複指定、上限超過は実行前に拒否します。出力は要約中心です。

```sh
.venv/bin/python tests/run_tests.py --list
# 実行は累計予算を明示承認された場合のみ
.venv/bin/python tests/run_tests.py --limit 10
```

`--list`は選択の確認だけで、テスト本体の実行は0件です。テストmoduleのimportは行うため、import時の副作用を起こすfixtureは作りません。既存の重点caseには複数のassertがありますが、全件suiteを一つのtest関数へ隠して上限を回避する運用はしません。

## CIも小さくする

自動CIはPRイベントだけ、Python 3.13だけ、その修正の明示選択だけです。今回branchは10項目案（未実行・累計増枠待ち）であり、CIを常時全件にする変更はしていません。同じ変更でpushとPRの両方・複数Python版・全体回帰・複数のwheel受入スクリプトを重複して走らせません。wheelはビルドのみ行い、追加の動作検査は自動では実行しません。

各試行でローカル何件・CI何件・再実行何件かを数えます。過去のGate3試行は取得ローカル4＋取得CI3＋rollback CI3＋忘却CI3で13項目・4回。今回修正では本体0件です。外部AIの実行報告を当方の受入へ足したり、branch変更で枠をリセットしたりしません。CI再実行や追加pushも再実行として予算に含めます。

10件を超える検査が本当に必要になった場合は、その理由と残る不安を示して明示的な増枠を確認します。文書だけの低影響変更では原則として新しいテストを追加せず、必要箇所のレビューに留めます。
