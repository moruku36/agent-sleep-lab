# 実装ロードマップ

現在の進捗・マージ状態・テスト結果は[実装状況](implementation-status.ja.md)のみに集約します。以下は成果物と完成条件であり、全項目が未実装という意味ではありません。

| 段階 | 成果物 | 完了条件 |
|---|---|---|
| 記録・採用・取得 | 原証拠、出典、scope、policy、受領、SQLite snapshot | 原子的採用、撤回、現在policy再検査、削除後の非復活 |
| Light／Deep | 証拠本文、生成した記憶文、run・予算・中断台帳、provider | 実モデルで本文→記憶案を確認し、独立検証を経て採用・取得まで到達 |
| 論文fixture比較 | 独立raw選択、固定した異なるA/B入力、完全な結果と費用 | 五つの開発課題で実応答を取得し、欠測も分母に含めて評価。fake合格を実評価としない |
| 既存agent一つ | 対象側の明示的capture/retrieve adapter | 対象の権限を維持し実行・利用を確認、前版へ戻せる |
| 任意の後続 | REM、日記、練習、wiki、横展開、定期処理 | 独立評価と総費用を確認してから別途判断 |

初期版の完成条件に含めるのは最初の四段階です。重み更新は別の研究トラックで、外部記憶の完成をGoogle Sleepの再現と呼びません。

[全体設計](architecture.ja.md)／[採用・復旧・取得の契約](contracts-and-acceptance.ja.md)／[実行手順](runtime-guide.ja.md)を併せて適用します。最終集合への再接触は開発データとして記録し、独立holdoutとしません。手動下書きの一度だけの取り出しは実agent接続・配信・利用の確認ではありません。

## 接続・運用のバックログ

[忘れるagentとの接続](dots-integration.ja.md)、[複数依頼の追跡・無応答・復旧](dots-multitask-reliability.ja.md)は対象側の接続設計です。記憶整理でサービスのフリーズを直せるとは主張しません。新ランタイム、専用DB、スケジューラーの追加は初期版の前提ではありません。
